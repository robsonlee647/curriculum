Stages 3 – 5

Backend

One Todo API, rebuilt three times. Same routes, same DTOs — each stage swaps in exactly one new concept: the framework, then the database, then identity.

Stage 3

NestJS

The simplest possible NestJS REST API — no auth, no database. An in-memory array stands in for storage so the framework's shape is the only thing to learn: module → controller → service → DTO.

MethodPathDescription
GET/api/todosAll todos, filterable by done / priority
POST/api/todosCreate a todo
PATCH/api/todos/:id/toggleFlip done ↔ undone
DELETE/api/todos/:idDelete

Stage 4

TypeORM + PostgreSQL

The same Todo API, now backed by a real PostgreSQL database via TypeORM. The point of the exercise: the HTTP layer doesn't change at all.

Stage 5

Firebase Authentication

Identity arrives last, on purpose — once the CRUD shape is second nature, layering a guard and a user relationship on top is a small, legible change. Every user now sees and manages only their own todos.

Client signs in via Firebase → ID token (JWT) → FirebaseAuthGuard verifies → request scoped to user
